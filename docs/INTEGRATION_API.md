# Public integration index v1 — design contract

Status: proposed implementation contract for #833; not a live endpoint. Consumers: Joomla field and module in jeckodevelopment/operaplus-extensions#1.

## Isolation
Read a coherent, validated published catalog snapshot and its companion channels; verify manifest hashes and counts. Never rewrite v2 manifest, channels, identities, or frontend. New outputs only under public/integrations/v1/. Run an independent workflow on successful publication (and manual dispatch); pin snapshot, serialize integration publications, reject stale overwrite, publish atomically using dedicated allowlisted paths. Do not add a blocking dependency or shared concurrency cancellation to refresh-catalog. On failure retain last known good and report independently. No SFTP deployment required for GitHub-hosted JSON.

## Shape
UTF-8 JSON object: schema_version: 1; source_revision: full commit SHA; catalog_reviewed_on: ISO date from manifest; entities: array sorted by type then id.
Each entity: type (opera|composer|theatre|festival|production), id (opaque stable string scoped by type), title (nonempty), subtitle (string or null), url (canonical public HTTPS URL or null), composer_ids (array of stable composer IDs), image (object or null), fallback_image (object or null), aliases (array of strings). Production optionally has production_kind (staging|group|program); IDs retain existing namespace or use explicit kind prefix to prevent collisions. Do not conflate staging with group or invent routes. Image object: url, alt, source_url, author, license, license_url, credit; required verified rights before reuse. Null means unavailable, never a guessed URL. No season entities or recite entities in v1.

## Source mapping
- opera: works channel, existing id, title, composer; canonical /atlas/opere/{route_slug or slug}/, validated by current routing; poster from existing work-posters companion if reuse rights verified.
- theatre: use published venue directory (including directory-only theatres); reconcile IDs to venues channel where supported, persist mapping if needed, no title-derived ID regeneration; canonical city/venue route from existing prerender rules.
- production: existing stagings (url), production-groups (existing group routes), published programs only when their public route and identity are verified. Keep distinct kinds.
- festival: festival-directory companion; use permanent id, never edition id; canonical /atlas/directory.html?section=festival&id={id}. Historical edition links resolve client-side to the permanent identity. Use registered image subject to rights.
- composer: independent additive registry, stable ID and aliases; derive candidate list from all works, including joint composer credits with explicit editorial disambiguation. No assumptions that a public composer detail route exists. url=null until a verified public route is available. Consumers may select composers but must omit invalid CTA or hide box according to configuration.

## Portrait registry
New data/composer-registry.json and data/composer-portraits.json; do not alter existing canonical catalog. Explicit mappings from work IDs to composer IDs; preserve ambiguous names for editorial review, no automated fuzzy merge. Target all composers represented in Atlas. Prefer verified public domain or compatible licensed portraits; record source, author, license URL, credit, alternate text, review date and reuse restrictions. No image until rights verified. Work box prefers verified composer portrait then verified work image; production prefers verified production art then work art. Theatre/festival use their verified images. No external scraping at Joomla request time.

### Automated portrait acquisition and coverage

`Refresh composer portraits` runs daily, on relevant main changes or by manual dispatch. It only writes the portrait registry and its independent review report. Verified records are preserved, transient Wikimedia failures are retried, and atomic checkpoints retain successful acquisitions even when another composer cannot be processed. The scan stops after three consecutive upstream errors or the time budget; unattempted composers remain explicitly identified. No upstream failure is treated as an absent image. Public-domain acceptance requires Copyrighted=false, identified author, no declared restrictions and either an explicit Commons Public Domain Mark URL or the Commons machine-readable PD code plus a specific combined source-country and US expiry category (PD-old-70/75/80/90/95/100-expired or corresponding PD-Art/PD-scan categories). When the URL is absent, the file description page is retained as the rights evidence URL; no license URL is invented. The explicit CC-PD-Mark category also supplies mark evidence when the API omits the URL, provided the PD code, non-copyrighted flag, attribution and source checks agree. Generic PD labels and US-only categories are insufficient. Reject explicit missing-source/author maintenance categories and repeated unknown-author placeholders. Canonical Creative Commons deed URLs are normalized, and CC BY / BY-SA 2.0 and 2.5 are recognized alongside 3.0 and 4.0. CC BY-SA 3.0 Germany retains its exact ported license URL and identifier. A Commons-generated raster thumbnail can be used for a non-raster original; both official upload.wikimedia.org and thumb.wikimedia.org are accepted for images, with a validated original-file fallback for raster originals. Lookalike hosts and non-HTTPS URLs remain rejected. Each rejected candidate records its file, source URL, reported license, author, restriction and evidence category in the independent review report. See https://commons.wikimedia.org/wiki/Commons:Machine-readable_data and https://commons.wikimedia.org/wiki/Commons:International_copyright_quick_reference_guide. The governance dashboard reads coverage directly from the composer and portrait registries, with review reasons and last attempt when available. A missing report never blocks other diagnostics. Exact Italian and English Wikipedia page titles (including redirects and aliases) resolve identities without the full-text search service; Wikidata search is the fallback, and EntityData is the alternate direct QID lookup. Every candidate must still pass exact identity and occupation verification. Confirmed QIDs are cached in the review report independently of the image rights decision and revalidated on subsequent scans. Up to eight P18 candidates are tried in preferred-rank order, retaining the same rights checks. If none qualifies, search Commons MediaInfo for P180 (depicts) using the confirmed QID, independently verify the returned statements, and accept only candidates with that sole structured depiction. This is structured identity evidence, not visual inspection; no filename-only or category-only fallback is permitted. Up to eight additional search candidates are checked. If those fail, up to two Commons categories explicitly linked by Wikidata P373 or the Commons sitelink are inspected (50 direct files per category, MediaInfo requests in batches of 20). Up to eight further candidates must have the sole verified P180 depiction of the composer; category membership alone does not qualify. Identity matching checks labels and aliases across languages while retaining exact normalized name, human and composer occupation requirements. Individual candidate failures do not prevent testing alternatives; unresolved upstream failures retain candidate diagnostics. Exact Wikipedia title lookup also considers composer-qualified titles in Italian and English. The oldest attempted identities are processed first, with unattempted composers ahead of them, to avoid starvation. A fully blocked scan commits diagnostics and then fails the workflow; a partial scan publishes progress and warns. The integration index remains a separate downstream publication.

## Consumer behavior
Fetch fixed trusted HTTPS endpoint using bounded timeouts and size, validate schema, types, IDs, links, image permissions and relationships. Cache last known good independently of failed refresh; never store unvalidated data. Prevent SSRF (no arbitrary endpoints or redirect destinations), escape output. Field stores ordered type+id references and optional primary reference; no copied title/URL. Module resolves at render time, manual/context mode, hides missing entities and never links to nonexistent pages. Unknown additive fields ignored; incompatible major version rejected.

## Acceptance
Deterministic export for same snapshot; unique type/id pairs; referential integrity; canonical route verification, explicit null fallback; tests for malformed inputs, duplicate identifiers, ambiguous composer names, invalid rights, malicious URLs, stale snapshot and failed publication. Compare existing catalog output bytes before/after at same input. Verify independent workflow cannot block or cancel refresh; previous valid index survives failures. Validate actual public endpoint before declaring delivery. No endpoint or workflow implementation included in this documentation PR.

Editorially reviewed Commons file leads can be stored in `data/composer-portrait-candidates.json`, keyed by the stable Atlas composer ID and exact registry name. They are considered before automatic image candidates after Wikidata identity confirmation; all existing rights and attribution gates still apply. The initial leads cover Franz Lehár and Samuel Barber. Other residual composers require additional research; candidate inclusion is not approval for publication.
